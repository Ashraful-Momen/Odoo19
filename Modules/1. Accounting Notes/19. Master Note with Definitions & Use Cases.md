# PART 0 : Foundation — ৩টা জিনিস জানলেই Accounting জানো

## ১. Accounting Equation

### 📖 Definition

- Accounting Equation = Double-entry system-এর ভিত্তি সূত্র, যা company-র financial position-কে mathematically represent করে।
- **Formula:** `Assets = Liabilities + Equity`
- সহজ ভাষায়: কোম্পানির যা আছে (Assets), তার কিছু অংশ দেনা (Liabilities), বাকিটা মালিকের (Equity)।

### 📋 Use Cases

- Balance Sheet তৈরির foundation.
- প্রতিটা transaction-এর প্রভাব বুঝতে — Assets, Liabilities, Equity-এর মধ্যে কার কতটুকু পরিবর্তন হলো।
- Audit trail verify করতে — equation mismatch মানেই কোনো entry ভুল বা incomplete.
- Financial health check: Equity = Assets − Liabilities (মালিক আসলে কতটুকুর মালিক)।

---

```
Assets = Liabilities + Equity
```

```
যা আছে  =  যাদের দেনা + মালিকের
```

সবসময় মিলবে। এটাই পুরো Accounting-এর ভিত্তি।

## ২. পাঁচটা Account Type

### 📖 Definition

- Account Type = COA-র প্রতিটা account-এর nature/category, যা ঠিক করে entry-তে debit হবে নাকি credit হবে এবং report-এ কোথায় বসবে (Balance Sheet নাকি P&L)।

### 📋 Use Cases

- Journal Entry তৈরি করার সময় সঠিক account select করতে।
- Report generation-এ auto-classification: Asset/Liability/Equity → Balance Sheet, Income/Expense → P&L.
- Debit/Credit rule (DEA-LIC) apply করতে account type জানা mandatory.
- Developer-দের জন্য: account_account table-এ account_type field filter করে report query লেখা।

---

```
Asset      → যা আছে        (Cash, Bank, Inventory, Laptop)

Liability  → যা দিতে হবে    (Loan, Payable, VAT)

Equity     → মালিকের        (Capital, Retained Earnings)

Income     → আয়            (Sales, Service)

Expense    → খরচ            (Salary, Rent, COGS)
```

## ৩. Debit / Credit Rule (DEA-LIC)

### 📖 Definition

- DEA-LIC = Debit/Credit-এর golden rule মনে রাখার mnemonic/acronym.
- **DEA** (Debit যখন বাড়ে — Dividend/Withdrawal, Expense, Asset) বাড়লে → Debit, কমলে → Credit.
- **LIC** (Liability, Income, Capital/Equity) বাড়লে → Credit, কমলে → Debit.

### 📋 Use Cases

- প্রতিটা Journal Entry-তে কোন account debit হবে, কোনটা credit হবে — এই rule দিয়েই determine করা হয়।
- Double-entry verification: Debit Total = Credit Total check করার জন্য।
- Developer: `account.move.line`-এর `debit` আর `credit` field-এ value বসানোর logic লেখার সময়।
- Invoice, Bill, Payment, Manual Entry — সবখানেই DEA-LIC apply হয়।

---

```
DEA বাড়লে Debit        LIC বাড়লে Credit

D = Debit                L = Liability
E = Expense              I = Income
A = Asset                C = Capital (Equity)
```

| Account   | বাড়লে | কমলে |
| --------- | ------------ | -------- |
| Asset     | Debit        | Credit   |
| Expense   | Debit        | Credit   |
| Liability | Credit       | Debit    |
| Equity    | Credit       | Debit    |
| Income    | Credit       | Debit    |

> **Golden Rule: প্রতিটা Entry-তে Debit Total = Credit Total। না মিললে Entry-ই হয় না。**

## Chart of Accounts (COA)

### 📖 Definition

- COA = Company-র সব Financial Account-এর Master List / Directory.

### 📋 Use Cases

### 📌 Current Asset vs Fixed Asset

#### 📖 Definition

- **Current Asset** = যে asset ১ বছরের মধ্যে cash/use হয়ে যাবে — Cash, Bank, Inventory, Receivable (short-term)।
- **Fixed Asset** = যে asset ১ বছরের বেশি টিকবে, ব্যবসায় ব্যবহারের জন্য কেনা — Laptop, Furniture, Vehicle, Building (long-term)।
- মূল পার্থক্য: সময় — Current Asset = short-term (liquidity), Fixed Asset = long-term (productivity)।
- Current Asset সহজে cash-এ convert হয়, Fixed Asset ধীরে ধীরে Depreciation-এর মাধ্যমে expense হয়।

#### 📋 Use Cases

- Balance Sheet-এ Current Asset আগে বসে, Fixed Asset পরে — liquidity priority order অনুযায়ী।
- Working Capital = Current Assets − Current Liabilities — daily operation capacity measure.
- Fixed Asset → Depreciation (ধীরে expense), Current Asset → direct consumption/sale (COGS/Cash)।
- Loan application: bank Current Asset দেখে short-term repayment capacity, Fixed Asset দেখে collateral value.
- Developer: `account_account` table-এ `account_type` = `asset_current` vs `asset_fixed` filter, `_search_is_current_asset()` domain logic।

## Journal

### 📖 Definition

- Journal = Transaction-এর Category/Container — কোন ধরনের/Department-এর ঘটনা সেটা classify করে।
- প্রতিটা Journal Entry একটা Journal-এর অধীনে থাকে।
- সহজে: Sales-এর ঘটনা Sales Journal-এ, Payment-এরটা Bank Journal-এ — যাতে খুঁজতে সুবিধা হয়।

### 📋 Use Cases

- Transaction type অনুযায়ী grouping: Sales, Purchase, Bank, Cash, Miscellaneous.
- Journal-wise reporting: কোন Journal-এর মাধ্যমে কত transaction হয়েছে তার overview.
- Dashboard-এ Bank Reconciliation screen-এ Journal select করে reconcile করা.
- Developer: `account_journal` table-এ `type` field (sale/purchase/bank/cash/general) use করে business logic.
- Access control — নির্দিষ্ট user-কে নির্দিষ্ট journal-এই entry দিতে দেয়া।

# PART 2 : Engine — Journal Entry (সবচেয়ে গুরুত্বপূর্ণ)

---

## Core Concept

### 📖 Definition

- Journal Entry = Double-entry system-এর বাস্তব রূপ — একটা Header (`account.move`) + তার Line গুলো (`account.move.line`) মিলে complete entry.
- প্রতিটা Entry-তে minimum ২টা line: একপাশে Debit, অন্যপাশে Credit (amount সমান)।
- সহজে: কোম্পানির খাতায় টাকার গতিবিধি লেখার formal record.

### 📋 Use Cases

- প্রতিটা financial transaction record করতে — বিক্রি, কেনা, payment, adjustment সবই।
- Audit trail: কে, কখন, কী entry দিলো তার complete record.
- Financial statement-এর building block — সব Report posted entry থেকেই বানানো হয়।
- Developer: `account.move` + `account.move.line` এই দুটো table-ই পুরো accounting module-এর core.

---

```
একটা Journal Entry = একটা account.move (Header)

তার লাইনগুলো     = account.move.line (Debit/Credit)
```

```
Move
│
├── Line 1: Debit   Bank      10,000
│
└── Line 2: Credit  Capital   10,000
```

## State

### 📖 Definition

- Journal Entry-র lifecycle stages: Draft → Posted → Cancel.
- Draft: সম্পাদনাযোগ্য, report-এ যায় না।
- Posted: Final/locked, report-এ visible, edit করা যায় না।
- Cancel: বাতিল করা entry (posted থেকে cancel করলে auto-reverse তৈরি হয়)।

### 📋 Use Cases

- Entry draft রেখে পরে review করে post করা — approval workflow implement করতে।
- Month-end/year-end closing-এ draft entries চেক করে post করা — incomplete entries যাতে report-এ না যায়।
- Developer: `state` field filter (state='posted') ভুলে গেলে Draft entries report-এ চলে আসে — এটা #1 bug.
- Audit: posted entries অপরিবর্তনীয়, draft track রাখে কী prepare হচ্ছে।

---

```
Draft    → লেখা হচ্ছে, Balance-এ যায় না, Edit যায়

Posted   → Final, Balance/Report Update, Edit যায় না

Cancel   → বাতিল
```

> **শুধু Posted Entry-ই Ledger ও Report-এ যায়।**

## Move Line-এর Field

### 📖 Definition

- `account.move.line` = Entry-র প্রতিটা Debit/Credit row, যেখানে account, amount, partner, date ইত্যাদি stored থাকে।

### 📋 Use Cases

- Account-wise balance calculate করতে — সব line-এর debit/credit sum করে।
- Partner ledger: partner_id filter করে customer/vendor-এর complete transaction history.
- Aged Receivable/Payable: date_maturity দেখে overdue calculate।
- Developer: `balance` field (signed: + = debit balance, − = credit balance), `reconciled` boolean, `full_reconcile_id` for matching.

---

```
account_id + partner_id + debit/credit + balance + date_maturity
```

## Posted Entry ভুল হলে

### 📖 Definition

- Posted entry edit করা যায় না — ঠিক করার legal/official উপায়: Reset to Draft অথবা Reverse Entry (উল্টো entry create)।

### 📋 Use Cases

- ছোট ভুল → Reset to Draft → Edit → Post (Audit trail partly preserved).
- বড়/পুরনো ভুল → Reverse Entry (নতুন entry previous entry-র উল্টো) — full audit trail preserved.
- Month/year closing-এর পর ভুল পেলে reverse entry-ই standard (reset করা যায় না locked period-এ)।
- Developer: `action_reverse()` method ব্যবহার, `_reverse_moves()` logic.

---

```
১. Reset to Draft → ঠিক করে আবার Post

২. Reverse Entry (উল্টো Entry)
```

## Manual Entry কখন?

### 📖 Definition

- Manual Entry = User নিজে হাতে তৈরি করা Journal Entry (automated না), Miscellaneous Journal-এ হয়।
- Opening balance, accrual, depreciation, prepaid release, correction, exchange difference-এর জন্য use হয়।

### 📋 Use Cases

- Opening Balance set করার সময় (নতুন company setup/migration).
- Month-end adjustment: accrued expense, prepaid release, depreciation.
- Correction entries (minor fix, reclassification).
- Exchange gain/loss entry (foreign currency revaluation).
- Developer: `move_type='entry'`, Miscellaneous Journal-এ `default_journal` logic.

---

```
Opening Balance, Depreciation, Accrual,

Prepaid, Correction, Exchange Difference

→ সবসময় Miscellaneous Journal-এ
```

```
Accounting → Accounting → Journal Entries → New
```


### 📌 Opening Balance

#### 📖 Definition

- **Opening Balance** = Company start/migration-এর সময় initial account balances — previous period/system-এর closing balance, new period-এ opening হিসেবে বসে।
- শুধু Permanent accounts (Asset/Liability/Equity)-এর opening থাকে, Income/Expense temporary — প্রতি year-এ zero থেকে start।
- Miscellaneous Journal + Manual Entry দিয়ে post করা হয়, fiscal year-এর first date-এ dated হয়ে থাকে।
- Double-entry maintain করে: সব Asset-এর opening Debit side-এ, Liability + Equity opening Credit side-এ — Total Debit = Total Credit।

#### 📋 Use Cases

- New company setup: owner capital, initial bank balance, opening stock — সব opening entry দিয়ে accounting start।
- System migration: legacy software থেকে Odoo-তে move করার সময় — Trial Balance closing → Odoo Opening Entry।
- Mid-year go-live: নির্দিষ্ট month-এ Odoo start — সেই date পর্যন্ত opening balances + current year transactions থেকে।
- Opening stock/inventory: warehouse items-এর quantity + value opening entry দিয়ে set — Inventory + Stock Input account use করে।
- Developer: opening entry-তে `date` field fiscal year first date set করতে হয়, `debit/credit` balance sign careful handling, `move_type='entry'`।

### 📌 Correction Entry

#### 📖 Definition

- **Correction Entry** = ভুল posted entry fix করার জন্য supplementary adjustment entry — wrong account, wrong amount, wrong partner fix।
- Original entry reverse না করে difference amount-এর জন্য additional entry (top-up/reclass/transfer) — audit trail অক্ষুণ্ণ থাকে।
- Miscellaneous Journal-এ manual entry হিসেবে post করা হয়, description-এ original entry reference দিতে হয়।

#### 📋 Use Cases

- Wrong expense account fix: Office Supplies-এ post হয়েছে, হওয়া উচিত ছিল Travel Expense → Dr Travel Exp / Cr Office Supplies (reclass entry)।
- Partial amount correction: $1,000 entry-তে $200 বেশি → reverse $200 difference only — rest intact।
- Period-end audit adjustment: auditor finding → correction entry → updated report without touching original posted entries।
- Wrong partner fix: A customer-র invoice B customer-এ post → Receivable account same, but partner_id wrong — correction entry with correct partner।
- Developer: always `move_type='entry'` with Misc Journal, original move reference store in `ref` or `narration` field, `_reverse_moves()` for full reversal alternative।
## Adjustment Entry-র ৫ ধরন

### 📖 Definition

- Adjustment Entry = Month/year-end-এ financial accuracy-র জন্য দেয়া special manual entries যা cash movement ছাড়াই account balance ঠিক করে।

### 📋 Use Cases

- Accrued Expense: মাস শেষে salary accrual, utility bill estimate.
- Accrued Income: service দিয়েছ কিন্তু invoice দেইনি — revenue recognition.
- Prepaid Expense: yearly insurance/rent — monthly release করতে।
- Unearned Revenue: customer আগে pay করেছে, service পরে দিবে।
- Depreciation: Fixed asset-এর value ধীরে ধীরে expense-এ convert করা।

---

```
Accrued Expense   → খরচ হয়েছে, টাকা যায়নি  (Dr Expense / Cr Payable)

Accrued Income    → Income হয়েছে, টাকা আসেনি (Dr Receivable / Cr Income)

Prepaid Expense   → টাকা গেছে, খরচ হয়নি     (Dr Prepaid / Cr Bank)

Unearned Revenue  → টাকা এসেছে, Service দেইনি (Dr Bank / Cr Unearned Rev)

Depreciation      → Asset ধীরে কমছে
```

# PART 3 : Daily Work — Payment + Bank

---

## Payment-এর Entry (মুখস্থ রাখো)

### 📖 Definition

- Payment Entry = Customer/Vendor থেকে টাকা আদান-প্রদানের Journal Entry।
- Customer Payment: টাকা আসছে → Dr Bank / Cr Receivable (Receivable কমছে — আমরা আর পাওনা না)।
- Vendor Payment: টাকা যাচ্ছে → Dr Payable / Cr Bank (Payable কমছে — আমরা আর দেনা না)।

### 📋 Use Cases

- Invoice/Bill-এর বিপরীতে payment receive/send করার সময়।
- Register Payment wizard use করলে auto entry + auto reconcile — manual entry avoid.
- Bank statement reconcile-এ payment match করার সময়।
- Developer: `account_payment` model → payment create করলে auto `account.move` তৈরি হয়।

---

```
Customer Payment:  Dr Bank / Cr Receivable

Vendor Payment:    Dr Payable / Cr Bank
```

## Partial Payment

### 📖 Definition

- Partial Payment = Invoice/Bill-এর complete amount-এর বদলে কিছু অংশ payment নেয়া/দেয়া।
- Payment State: Not Paid → Partial → Paid (amount_residual track করে)।

### 📋 Use Cases

# PART 5 : Tax — তুমি সরকারের মাঝমানুষ

## VAT-এর মূল কথা

### 📖 Definition

- VAT (Value Added Tax) = Consumption tax — প্রতি stage-এ value addition-এর উপর tax।
- Output VAT (Sales-এ collect): সরকারের কাছে জমা দিতে হবে = Liability।
- Input VAT (Purchase-এ paid): সরকার থেকে ফেরত পাওয়া যায় = Asset।
- Net: Output − Input = Payable (positive হলে pay, negative হলে refund)।

### 📋 Use Cases

- প্রতিটা Sale Invoice-এ VAT যোগ করে customer থেকে collect → Output VAT account (Liability)।
- প্রতিটা Purchase Bill-এ VAT সহ pay → Input VAT account (Asset, claimable)।
- Month-end Tax Report → Output − Input calculate → Tax Authority-তে payment।
- Developer: `account_tax` model, tax_id field on `account_move_line`, tax report generation logic.

---

```
বিক্রিতে তোলা VAT  = Output = তোমার না, সরকারের = Liability

কেনায় দেওয়া VAT = Input  = ফেরত পাবে        = Asset

মাস শেষে: Output − Input = সরকারকে Payment (বা Refund)
```

## Entry

### 📖 Definition

- Sales: Dr Receivable (full) / Cr Sales (net) / Cr VAT Payable (tax amount)।
- Purchase: Dr Expense/Asset (net) / Dr VAT Receivable (tax) / Cr Payable (full)।

### 📋 Use Cases

- Invoice line-এ tax apply করলে auto tax amount calculate → auto move line তৈরি।
- Tax-inclusive vs tax-exclusive pricing handle (price_include config)।
- Developer: tax_ids many2many → `_compute_all()` method → tax amount per line।

---

```
Sales $1,000 + 15% VAT:

Dr Receivable 1,150 / Cr Sales 1,000 / Cr VAT Payable 150
```

```
Purchase $1,000 + 15% VAT:

Dr Expense 1,000 / Dr VAT Receivable 150 / Cr Payable 1,150
```

## Withholding Tax (WHT)

### 📖 Definition

- WHT = Buyer/Client টাকা দেয়ার সময় নির্দিষ্ট % কেটে রেখে সরাসরি সরকারকে deposit করে — freelancer/contractor payment-এ common।
- Company-র কাছে এটা Payable (সরকারকে দিতে হবে), vendor কম টাকা পায়।

### 📋 Use Cases

- Freelancer/consultant payment: $1,000 invoice, 10% WHT → vendor পায় $900, $100 সরকারে জমা।
- Compliance: WHT certificate vendor-কে দেয়া — যাতে vendor ওই $100 নিজের tax-এ adjust করতে পারে।
- Developer: tax type = 'withholding', negative amount logic on vendor bill line।

---

```
Freelancer-কে $1,000, WHT 10%:

Dr Expense 1,000 / Cr Payable 900 / Cr WHT Payable 100

→ তুমি আটকে রেখে সরকারকে দাও
```

# PART 6 : Inventory Accounting (Odoo-র হৃদয়)

---

## মূল Concept

### 📖 Definition

- পণ্য কেনার সময় সেটা Expense না, বরং Asset (Inventory) — Balance Sheet-এ বসে।
- পণ্য বিক্রির সময় সেটা Expense (COGS = Cost of Goods Sold) — P&L-এ যায়।
- Profit = Sales − COGS — তাই inventory valuation সরাসরি profit-কে affect করে।

### 📋 Use Cases

- Product-based business-এ inventory accounting mandatory — actual profit calculation-এর জন্য।
- Balance Sheet accuracy: unsold goods asset-এই থাকবে, expense হবে না।
- Developer: `stock_valuation_layer` tracking, Perpetual vs Periodic valuation logic।

---

```
পণ্য কেনা = Expense না = Asset (Inventory)

পণ্য বিক্রি = তখনই খরচ = COGS

Profit = Sales − COGS
```

## বিক্রিতে দুইটা Entry

### 📖 Definition

- বিক্রির সময় দুইটা simultaneous entry: (A) Sales price-এ Receivable + Income, (B) Cost price-এ COGS + Inventory reduction।
- Double-entry accounting-এ inventory-র movement track করতে দুইটা entry mandatory।

### 📋 Use Cases

- Automated inventory valuation: sales order confirm → delivery → auto COGS entry।
- Profit margin calculation per transaction: Sales − COGS = Gross Profit।
- Developer: `_stock_account_prepare_anglo_saxon_in_lines_vals()` method logic।

---

```
A) দামে:      Dr Receivable / Cr Sales

B) কেনা দামে: Dr COGS / Cr Inventory
```

## Perpetual (Automated) Flow

### 📖 Definition

- Perpetual/automated inventory = প্রতিটা stock move (receive/deliver)-এর সাথে সাথে auto journal entry create হয়।
- Manual entry লাগে না, real-time inventory valuation maintained থাকে।

### 📋 Use Cases

- Product Category-তে costing method + automated valuation set → stock move হলেই entry auto post.
- Real-time stock value tracking — monthly/yearly physical count-এর dependency কমে।
- Developer: `stock.move` → `stock.valuation.layer` → `account.move` — 3-layer automation pipeline।

---

```
Receive পণ্য:    Dr Inventory / Cr Stock Input (GRNI)

Bill Post:       Dr Stock Input / Cr Payable

Deliver পণ্য:    Dr Stock Output / Cr Inventory

Invoice Post:    Dr COGS / Cr Stock Output (+ Sales Entry)
```

```
GRNI = Goods Received Not Invoiced

= পণ্য এসেছে, Bill আসেনি — Bridge Account
```

### 📌 GRNI + Stock Input / Stock Output Accounts

#### 📖 Definition

- **GRNI** (Goods Received Not Invoiced) = Stock Input Account, temporary bridge/suspense account — পণ্য warehouse-এ এসে গেছে কিন্তু vendor bill এখনো আসেনি।
- **Stock Input Account** = Receive পণ্য → Dr Inventory / Cr Stock Input → Bill post হলে → Dr Stock Input / Cr Payable → account zero হয়ে যায় (clearing account)।
- **Stock Output Account** = Deliver পণ্য → Dr Stock Output / Cr Inventory → Invoice post হলে → Dr COGS / Cr Stock Output → account zero হয়ে যায় (clearing account)।
- দুইটাই temporary clearing account — final position zero, শুধু timing difference (goods vs invoice) manage করে।

#### 📋 Use Cases

- Goods receive before vendor bill: warehouse receipt → credit GRNI → Inventory + Liability properly recorded at correct time.
- Month-end financial reporting: GRNI balance ≠ 0 মানে "goods received but not invoiced" — Accrued Liability report.
- Stock Output tracking: goods delivered but customer invoice pending — COGS deferral manage।
- Audit trail: GRNI/Stock Output movement → vendor/customer invoice match verification.
- Developer: stock input/output default accounts configure at Product Category level (`property_stock_account_input/output`), `stock.valuation.layer` → `account.move` trace।

## Costing Method

### 📖 Definition

- Costing Method = Inventory-র Unit Cost কীভাবে calculate হবে: FIFO (first-in-first-out), AVCO (average cost), Standard (fixed predetermined cost)।
- Product Category-র level-এ set করা হয়, পুরো category-র সব product-এ apply হয়।

### 📋 Use Cases

- FIFO: inflation-এ inventory value বেশি দেখায়, COGS কম — higher profit (perishable goods)।
- AVCO: সব purchase average করে — stable costing, সহজ calculation (manufacturing)।
- Standard: budget vs actual variance analysis (manufacturing with stable costs)।
- Developer: `product.category`-তে `property_cost_method` field, valuation layer-এ unit_cost compute।

---

```
FIFO     → আগেরটা আগে বিক্রি
```

# PART 7 : Fixed Assets

---

## মূল Concept

### 📖 Definition

- Fixed Asset = ব্যবসায় ব্যবহারের জন্য কেনা জিনিস, যা ১ বছরের বেশি টিকবে — Laptop, Furniture, Vehicle, Building।
- একবারে Expense না, purchase-এ Asset হয়ে প্রতি মাসে Depreciation (খন্ড খন্ড expense) হয়।
- Matching principle: asset use করার পুরো life-এই expense spread করা হয়, একবারে না।

### 📋 Use Cases

- Capital expenditure (CAPEX) vs Operating expenditure (OPEX) আলাদা করতে।
- Tax benefit: depreciation deductible expense — annual tax filing-এ কাজে লাগে।
- True profit calculation: পুরো machine cost এক মাসে দেখালে profit artificially কমে যাবে।
- Developer: `account_asset` model, auto depreciation entry scheduler (cron)।

---

```
ব্যবহারের জন্য কেনা + ১ বছরের বেশি টিকবে = Fixed Asset

কেনার মুহূর্তে Expense না

প্রতি মাসে একটু করে Expense = Depreciation
```

## Entry

### 📖 Definition

- Purchase: Dr Asset (Balance Sheet) / Cr Bank।
- Monthly Depreciation: Dr Depreciation Expense (P&L) / Cr Accumulated Depreciation (Contra-Asset, Balance Sheet)।
- Accumulated Depreciation Asset-এর value কমায় — Book Value = Cost − Accumulated Depreciation।

### 📋 Use Cases

- Monthly auto depreciation: Odoo scheduler create করে journal entry প্রতি মাসে।
- Asset register: asset-wise cost, accumulated depreciation, book value track।
- Tax filing: depreciation schedule-এর সাথে tax authority-র allowed rate match করা।
- Developer: `account_asset.depreciation.line` model, `_compute_depreciation_board()` method।

---

### 📌 Contra-Asset (Accumulated Depreciation)

#### 📖 Definition

- **Contra-Asset** = Asset-এর opposite nature account — Asset বাড়লে Debit, কিন্তু Contra-Asset বাড়লে Credit (LIC rule-এ চলে)।
- **Accumulated Depreciation** সবচেয়ে common Contra-Asset — Fixed Asset-এর value reduce করার জন্য accumulate করা total depreciation amount।
- Normal Asset-এর credit balance version — Balance Sheet-এ Asset-এর নিচে minus/negative হিসেবে বসে।
- Book Value = Asset Cost − Accumulated Depreciation — Contra-Asset যত বাড়ে, Net Asset value তত কমে।

#### 📋 Use Cases

- Fixed Asset depreciation tracking: প্রতি মাসে Dr Depreciation Expense / Cr Accumulated Depreciation — Asset original cost unchanged, Contra-Asset-এ accumulate হয়।
- Asset disposal: Accumulated Depreciation reverse → Dr Acc. Dep (remove) / Cr Asset — net gain/loss calculate।
- Financial reporting transparency: Balance Sheet-এ Asset cost + Accumulated Depreciation আলাদা দেখায় — reader বুঝতে পারে asset কত পুরনো।
- Tax vs Book depreciation: separate Accumulated Depreciation accounts for different depreciation rates/methods।
- Developer: `account_type` = `asset_depreciation`, debit/credit sign opposite of normal asset, `_get_asset_depreciation_account()` method।

```
কেনা:         Dr Asset / Cr Bank

প্রতি মাসে:    Dr Depreciation Expense / Cr Accumulated Depreciation
```

## হিসাব

### 📖 Definition

- Straight Line Method: (Purchase Price − Salvage Value) ÷ Useful Life (months/years)।
- Declining Balance Method: Book Value-র নির্দিষ্ট % — শুরুতে বেশি depreciation, পরে কম।

### 📋 Use Cases

- Straight Line: evenly distributed expense — furniture, building (stable usage pattern)।
- Declining: tech equipment — শুরুতে fast depreciation (realistic value drop)।
- Developer: `account_asset`-এ `method` field (linear/degressive), `_compute_depreciation_board()`।

---

```
Straight Line: দাম ÷ জীবনকাল (মাস)

Book Value = কেনা দাম − Accumulated Depreciation
```

## Disposal (বিক্রি)

### 📖 Definition

- Asset বিক্রি/remove করার সময় entry: Bank (sale price) + Accumulated Depreciation remove + Asset (cost) remove + Gain/Loss (পার্থক্য)।
- Book Value-র চেয়ে বেশিতে বিক্রি → Gain, কমে → Loss।

### 📋 Use Cases

- Old laptop/furniture sell → dispose entry, gain/loss P&L-এ reflect।
- Asset retirement (scrap): sale price zero, পুরোটাই loss।
- Developer: `account_asset`-এ `action_sell()` / `action_dispose()` method।

---

```
Dr Bank (বিক্রি মূল্য)

Dr Accumulated Depreciation (মোট জমানো)

Cr Asset (কেনা দাম)

পার্থক্য → Gain / Loss
```

## Odoo-তে

### 📖 Definition

- Vendor Bill-এ Asset Account select করলে Odoo auto `account_asset` record তৈরি করে, তারপর cron scheduler প্রতি মাসে auto depreciation entry post করে।

- Month-end: scheduler auto post করে — manual intervention লাগে না।
- Developer: `account_asset` model, `account_asset.depreciation.line`, cron `account_asset.assets_generate_entries`।

## Trial Balance

### 📖 Definition

- Trial Balance = সব Account-এর Debit ও Credit Balance-এর summarized list — period-end-এ check করার tool।
- Golden check: Total Debit Balance = Total Credit Balance — match করলে double-entry mathematically correct।
- Warning: ভুল account-এ entry দিলেও TB match করে — TB match ≠ 100% accurate।

### 📋 Use Cases

- Month-end প্রথম check: TB দেখে debit/credit mismatch থাকলে investigate।
- Account balance sanity check: negative asset, credit balance expense → suspect entry।
- P&L + Balance Sheet prepare-এর আগে TB verify করা standard practice।

---

```
সব Account-এর Debit/Credit Balance

Debit Total = Credit Total মিললে ✓

(তবে ভুল Account-এ Entry থাকলেও মিলে — সাবধান)
```

## P&L vs Balance Sheet

### 📖 Definition

- P&L (Profit & Loss) = নির্দিষ্ট সময়ের ফলাফল → Income − Expense = Profit/Loss (flow report)।
- Balance Sheet = নির্দিষ্ট দিনের financial position-এর ছবি → Assets = Liabilities + Equity (snapshot report)।

### 📋 Use Cases

- P&L: মাসে/বছরে লাভ-ক্ষতি কত — performance evaluation, tax calculation।
- Balance Sheet: এই মুহূর্তে company-র net worth (Equity) কত — investor/lender-কে দেখানোর জন্য।
- Year-end: P&L-র profit → Balance Sheet-এর Retained Earnings-এ transfer হয়।

---

```
P&L           = সময়ের ফলাফল (Income − Expense = Profit)

Balance Sheet = দিনের ছবি (Assets = Liabilities + Equity)
```

# PART 9 : Fiscal Year — বছর শুরু ও শেষ

---

## দুই ধরনের Account

### 📖 Definition

- Permanent (Real) Accounts: Asset, Liability, Equity — year-end-এ zero হয় না, balance forward হয়।
- Temporary (Nominal) Accounts: Income, Expense — year-end-এ zero করে difference (profit/loss) Retained Earnings-এ transfer হয়।

### 📋 Use Cases

- Year-end closing: Odoo auto income/expense → 0, profit → Retained Earnings — manual entry লাগে না।
- Opening balance: permanent accounts-এর balance auto carry forward — নতুন year-এ same balance থেকে start।
- Developer: closing entry generation logic, permanent vs temporary account type check।

---

```
Permanent (বয়ে যায়):  Asset, Liability, Equity

Temporary (শূন্য হয়):  Income, Expense

→ পার্থক্য (Profit) যায় Retained Earnings-এ
```

## বছরের Cycle

### 📖 Definition

- Fiscal Year-এর complete lifecycle: Opening → Daily Transactions → Monthly Adjustments → Year-End Closing → Lock → New Year start।

### 📋 Use Cases

- Year setup: Accounting → Settings → Fiscal Year define (Jan-Dec / Jul-Jun)।
- Month-end routine: adjustments post → reports verify → period lock।
- Year-end: all adjustments posted → auto closing entry → hard lock → fresh start।
- Audit: locked period-এ ভুল ধরা পড়লে auditor adjustment পরের period-এ।

---

```
Opening Entry (শুধু নতুন Setup/Migration-এ)

   ↓

সারা বছর: Entry + Invoice + Payment

   ↓

প্রতি মাসে: Report + Adjustment + Lock

   ↓

বছর শেষে: সব Adjustment Post

   ↓

Odoo নিজে: Income/Expense → 0, Profit → Retained Earnings

   ↓

Hard Lock Date → নতুন বছর শুরু
```

## Lock Date

### 📖 Definition

- Lock Date = নির্দিষ্ট date-র আগের period-এ entry edit/create block করার mechanism।
- Soft lock (Tax/Sale/Purchase user-দের জন্য) + Hard lock (সবার জন্য, irreversible without setting change)।

### 📋 Use Cases

- Month-end: period lock করে accidental entry prevent।
- Audit compliance: audited period lock করে রাখা — কেউ modify করতে পারবে না।
- Multi-user environment-এ safety: কেউ পুরনো period-এ ভুল entry দিয়ে report নষ্ট করতে পারবে না।

---

```
Final Period-এ Entry বদলানো বন্ধ করে

Accounting → Accounting → Lock Dates

(Tax / Sale / Purchase / All Users / Hard Lock)
```

> **Odoo-তে Closing Entry হাতে দিতে হয় না — Automatic।**

## Budget

### 📖 Definition

- Budget = Plan vs Actual comparison — Analytic Account-এর উপর ভিত্তি করে estimated vs real spending track করা।

### 📋 Use Cases

- Annual budgeting: department-wise budget set → monthly actual tracking → variance analysis।
- Project cost control: budget vs actual alert → overspend prevent।
- Management reporting: budget utilization percentage — performance review।

---

```
Budget             → Plan vs Actual (Analytic-এর উপর)
```

## Multi Currency

### 📖 Definition

- Multi Currency = Invoice/Bill এক currency-তে, Company-র accounting অন্য currency-তে (base currency) — Odoo auto currency conversion + exchange rate maintain করে।

### 📋 Use Cases

- International sales: customer USD-এ invoice, company books BDT-তে — auto conversion।
- Foreign vendor: EUR-এ bill, BDT-তে record — rate apply করে entry।
- Revaluation: month-end-এ outstanding foreign currency items revalue — exchange gain/loss capture।

---

```
Multi Currency     → Invoice এক মুদ্রায়, হিসাব অন্য মুদ্রায়
```

## Exchange Difference

### 📖 Definition

- Exchange Difference = Invoice date-র rate আর Payment date-র rate-এর পার্থক্য — currency fluctuate করলে gain বা loss হয়।
- Payment-এর সময় auto exchange entry তৈরি হয় (Odoo handle করে)।

### 📋 Use Cases

- Foreign customer payment: invoice-র সময় rate 110 BDT/USD, payment-এর সময় 115 → exchange loss 5 BDT per USD।
- Month-end revaluation: outstanding foreign currency AR/AP revalue → unrealized gain/loss entry।
- Developer: `_create_exchange_difference_move()` method, exchange journal configuration।

---

```
Exchange Diff      → Invoice-Rate vs Payment-Rate

                     পার্থক্য = Exchange Gain/Loss (Auto Entry)
```
