# Module 5: Payment — Odoo 19 Complete Note

আজ আমরা শিখব **টাকা আসা-যাওয়ার Accounting**।

> **Invoice মানে পাওনা, Bill মানে দেনা। কিন্তু Business-এর আসল জীবন হলো Payment—টাকা আসা আর টাকা যাওয়া। এই Module বুঝলে Receivable-Payable-এর পুরো খেলা ক্লিয়ার হয়ে যাবে।**

# Chapter 1 : Real Life Story

ভাবো তুমি একটা দোকানে মুদি কিনতে গেলে।

দোকানদার বলল—

```
"৫০০ টাকা হয়েছে"
```

```
"এখন ৩০০ দিচ্ছি, ২০০ পরে দেব"
```

```

```

```

# Chapter 2 : Payment-এর ধরন

দুই দিক আছে—

```
Customer Payment (টাকা আসে)

Vendor Payment (টাকা যায়)

---

## Customer Payment (Inbound)

Customer তোমার পাওনা দিল।

```
Debit    Bank / Cash          (Asset বাড়ল)

Credit   Accounts Receivable  (Asset কমল — পাওনা শেষ)
```

---

## Vendor Payment (Outbound)

তুমি Vendor-এর দেনা দিলে।

```
Debit    Accounts Payable     (Liability কমল — দেনা শেষ)

Credit   Bank / Cash          (Asset কমল)
```

---

# Accounting Logic

মনে রাখো—

```
Invoice-এ সময়

Receivable বেড়েছিল

↓

Payment-এ

Receivable কমে
```

```
Bill-এর সময়

Payable বেড়েছিল

↓

Payment-এ

Payable কমে
```

> **Payment মানে— Receivable বা Payable শূন্যের দিকে নিয়ে যাওয়া।**

# Chapter 3 : Partial Payment

Customer-এর বিল $5,000।

Customer দিল মাত্র $2,000।

Entry—

```
Debit    Bank                  $2,000

Credit   Accounts Receivable   $2,000
```

এখন অবস্থা—

```
মোট বিল          $5,000

পরিশোধিত         $2,000

Outstanding      $3,000   ← এখনো পাওনা
```

Invoice-এর Payment State হবে—

```
Partial
```

পুরো $5,000 পেলে—

```
Paid
```

# Chapter 4 : Reconciliation — সবচেয়ে গুরুত্বপূর্ণ Concept

এখানে মন দাও।

Invoice-এ একটা Move Line তৈরি হয়েছিল—

```
Accounts Receivable   Debit   $5,000
```

Payment-এ আরেকটা Move Line তৈরি হলো—

```
Accounts Receivable   Credit  $2,000
```

এই দুইটা লাইনকে **Match** করাকে বলে—

# Reconciliation

---

## কেন Match করা দরকার?

না করলে Odoo জানবে না—

```
কোন Payment

কোন Invoice-এর টাকা
```

Match করার পর Odoo জানে—

```
এই Invoice-এর

$2,000 এসেছে

$3,000 বাকি
```

---

## Reconcile হলে কী হয়?

```
Invoice-এর Receivable Line

        +

Payment-এর Receivable Line

        ↓

    Match (Reconcile)

        ↓

Invoice → Partial / Paid
```

---

## Partial vs Full Reconcile

```
কিছু টাকা Match   → Partial Reconcile

পুরো টাকা Match   → Full Reconcile
```

Database-এ—

```
account_partial_reconcile

account_full_reconcile
```

# Interview Questions

### 1. Customer Payment-এর Journal Entry কী?

**উত্তর:** Debit Bank (বা Cash), Credit Accounts Receivable।

---

### 2. Vendor Payment-এর Journal Entry কী?

**উত্তর:** Debit Accounts Payable, Credit Bank (বা Cash)।

---

### 3. Partial Payment কী?

**উত্তর:** পুরো বিলের কম টাকা পরিশোধ। Invoice তখন "Partial" State-এ থাকে, বাকিটা Outstanding হিসেবে দেখায়।

---

### 4. Reconciliation কী?

**উত্তর:** Invoice/Bill-এর Receivable/Payable Move Line-এর সাথে Payment-এর Move Line Match করা—যাতে জানা যায় কোন টাকা কোন বিলের।

---

### 5. Partial আর Full Reconcile-এর পার্থক্য?

**উত্তর:** কিছু অংশ Match হলে Partial Reconcile, পুরো Amount Match হলে Full Reconcile—তখন Invoice "Paid" হয়।

---

### 6. Outstanding Amount কী?

**উত্তর:** বিলের এখনো অপরিশোধিত অংশ (`amount_residual`)।

---

### 7. Customer Advance পেলে কী হয়?

**উত্তর:** Invoice ছাড়া টাকা এলে সেটা Outstanding Credit হিসেবে থাকে; পরে নতুন Invoice-এর সাথে Match করা যায়।

---

# Common Mistakes

❌ Payment-এর Manual Journal Entry করা—Invoice-এর সাথে Reconcile হয় না। সবসময় Register Payment ব্যবহার করো।

❌ ভুল Partner-এ Payment করা।

❌ ভুল Journal (Bank-এর জায়গায় Cash) Select করা।

❌ Partial Payment-কে আলাদা Invoice ভাবা।

❌ Reconcile না করে Report দেখা—Receivable ভুল দেখাবে।

❌ Payment Date আজকের দিলে, অথচ Bank-এ টাকা এসেছে অন্য দিন।

# Module 5 শেষ করার পর তোমার যা বোঝা উচিত

* Customer Payment = Debit Bank, Credit Receivable।
* Vendor Payment = Debit Payable, Credit Bank।
* Partial Payment হলে Invoice "Partial" থাকে, বাকিটা Outstanding।
* Reconciliation মানে Invoice আর Payment-এর লাইন Match করা।
* সবসময় Register Payment ব্যবহার করবে—Manual Entry না।
* `amount_residual = 0` মানেই Paid।
