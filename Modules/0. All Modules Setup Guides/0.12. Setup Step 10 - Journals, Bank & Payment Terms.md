# Setup Step 5 : Journals, Bank & Payment Terms

**Series: Odoo 19 Accounting Perfect Setup (Step 5 of 6)**

> **Journal হলো Transaction-এর রাস্তা। রাস্তা ঠিক থাকলে গাড়ি (Entry) নিজে নিজে গন্তব্যে পৌঁছে যায়। এই Note-এ Journal-এর প্রতিটা Field, Bank Setup, আর Payment Terms বানানো — সব করলে-কী-হয় না-করলে-কী-হয় সহ।**

---

# PART A : Journals

## কোথায়

```
Accounting → Configuration → Journals
```

## Localization-এ যা আসে

```
Sales            → Customer Invoice-এর জন্য

Purchase         → Vendor Bill-এর জন্য

Bank             → Bank Transaction-এর জন্য

Cash             → নগদ Transaction-এর জন্য

Miscellaneous    → Manual/Adjustment Entry-র জন্য
```

> **এই ৫টা ৯০% Company-র জন্য যথেষ্ট। আগে এগুলো ঠিক করো, তারপর ভাবো নতুন লাগবে কিনা।**

---

## Journal-এর প্রতিটা Field

### 1. Journal Name

```
কী:      "Sales", "Customer Invoices" এরকম নাম

Rule:   যে দেখলেই বোঝে এখানে কী হয়
```

### 2. Type 🚨

```
Sale / Purchase / Bank / Cash / General
```

```
কেন গুরুত্বপূর্ণ:

   Type-ই ঠিক করে এই Journal-এ

   কোন Document বানানো যাবে
```

```
ভুল দিলে:

   Bank Journal-এর Type "General" দিলে

   → Reconcile Screen-ে আসবে না

   → Bank Statement বানানো যাবে না
```

> **নতুন Journal বানালে Type দুইবার দেখো। পরে বদলালে পুরোনো Entry নিয়ে ঝামেলা।**

### 3. Short Code

```
কী:      ২-৫ Letter-এর Code (যেমন: SAJ, BNK1)

কী কাজে: Document Number এখান থেকে বানে

         SAJ/2026/0001, BNK1/2026/0001
```

```
করলে ভালো নাম্বারিং পাবে

না দিলে/একই Code দুই Journal-এ দিলে:

   Number গুলিয়ে যাবে, Audit-এ খুঁজতে কষ্ট
```

### 4. Default Account (Bank/Cash Journal-এ)

```
কী:      এই Journal-এর Entry কোন COA Account-এ যাবে

Bank Journal হলে: তোমার Bank Account (যেমন: 100201 Bank DBBL)

Cash Journal হলে: Cash Account
```

```
ভুল দিলে:

   ❌ Payment Bank-এ গেল, Entry অন্য Account-এ

   ❌ Bank Balance কখনো মিলবে না
```

### 5. Outstanding Receipts / Payments Account

```
কী:      "পথে থাকা টাকা"-র Account (Module 6 মনে আছে?)
```

```
ঠিক থাকলে:

   ✅ Payment আর Bank Statement-এর Gap Automatic Handle

   ✅ Bank Reconciliation একদম Smooth

ভুল/ফাঁকা থাকলে:

   ❌ Reconcile করলে Entry ভুল জায়গায় যায়
```

> **Localization-এ Auto বসে থাকে। শুধু খুলে Check করো বসে আছে কিনা — বদলিও না।**

### 6. Dedicated Payment Sequence

```
কী:      Payment-এর নম্বর আলাদা রাখবে কিনা

         (PAY/2026/0001 এরকম)
```

```
চালু করলে: Payment আলাদা Series-এ গোনা যায় → খোঁজা সহজ

না করলে:   Journal-এর সাথেই মিশে যায়
```

---

## কখন নতুন Journal বানাবে?

```
একাধিক Bank Account    → প্রতিটার আলাদা Bank Journal ✅

Credit Card Account    → আলাদা Bank-Type Journal ✅

আলাদা Cash Box (পেটি ক্যাশ) → আলাদা Cash Journal ✅
```

```
কখন বানাবে না:

   "ধরন আলাদা করতে চাই" ভেবে Sales Journal-এর কপি

   → Report জটিল হয়, লাভ কিছু নেই
```

# PART B : Bank Account Setup

## নতুন Bank Account যোগ করা

```
Accounting Dashboard → Add a Bank Account
```

বা

```
Accounting → Configuration → Bank Accounts → New
```

## প্রতিটা Field

### Account Number

```
কী:      Bank-এর আসল Account Number

কেন:    Statement Import-এ Match করতে লাগে

ভুল দিলে: Statement Line Match হবে না
```

### Bank (Bank Name)

```
কী:      কোন Bank

করলে:    Bank-এর Format অনুযায়ী Import সহজ হয়
```

### Journal

```
কী:      এই Account-এর Transaction কোন Journal-এ

নিয়ম:  নতুন Bank Journal বানাতে দাও (Auto)

         → Dashboard-এ আলাদা Card আসবে

         → প্রতিটা Bank-এর হিসাব এক চোখে
```

## Setup শেষে Check

```
□  Dashboard-এ Bank-এর Card দেখা যাচ্ছে

□  Card-এ Default Account ঠিক আছে

□  Outstanding দুইটা Account বসে আছে

□  একটা Test Payment করে Entry দেখেছি
```

# PART C : Payment Terms

## কোথায়

```
Accounting → Configuration → Payment Terms
```

## কী জিনিস

```
Invoice-এ কবে টাকা দিতে হবে — তার নিয়ম

→ এটা দিলে Due Date নিজে বের হয়

→ Due Date থেকেই Aged Receivable বানে
```

## Ready থাকে

```
Immediate Payment    → এখনই

15 Days              → ১৫ দিন

30 Days              → ৩০ দিন

End of Following Month → পরের মাসের শেষে
```

## নিজের বানানো — Example

### Example 1 : 50% Advance + 50% in 30 Days

```
Name: 50% Advance, 50% Net 30

Line 1: 50% → Due: Immediately

Line 2: 50% (Balance) → Due: 30 Days
```

```
করলে কী হয়:

   Invoice-এ দুইটা Due Date নিজে ভাগ হয়ে যায়

   → $10,000-এর Invoice-এ $5,000 আজকের Due,

     $5,000 ৩০ দিন পরের Due

   → Aged Report-ে দুইটা আলাদা Track হয়
```

### Example 2 : Software Company-র Classic

```
Name: Net 30

Line: 100% → Due: 30 Days after Invoice Date
```

```
কেন: মাস শেষে Invoice, পরের মাসে Payment — Industry Standard
```

## কোথায় বসবে

```
দুই জায়গায় Default দেওয়া যায়:

১. Customer-এর Profile-এ (res.partner)

   → ওই Customer-এর সব Invoice-এ নিজে আসবে ✅

২. Invoice বানানোর সময় হাতে

→ Rule: Customer-এর Profile-এ বসিয়ে দাও।

  হাতে বসালে একদিন ভুলে যাবেই।
```

```
না দিলে কী হয়:

   ❌ Due Date থাকে না

   ❌ Aged Report কাজ করে না

   ❌ কার টাকা কবে আসবে — কেউ জানে না

   ❌ পাওনা আদায় = ভাগ্যের উপর
```

# Common Mistakes

❌ দুই Journal-এ একই Short Code — Numbering গুলে যায়।

❌ Bank Journal-এর Type ভুল দেওয়া — Reconcile আসবে না।

❌ Outstanding Account ফাঁকা/ভুল — Bank Setup ভেঙে যায়।

❌ একটাই Bank Journal-এ দুইটা Bank Account — হিসাব মিশে যায়।

❌ Payment Terms Customer Profile-এ না দেওয়া — Due Date হারায়।

❌ "Net 30" লিখে কোনো Line না দেওয়া — Terms ফাঁকা।

❌ নতুন Journal-এ পুরোনো Entry নিয়ে ভাবা — পুরোনোটা পুরোনো Journal-এই থাক, নতুন Entry নতুন Journal-এ।

# Checklist

```
Journals—

□  ৫টা Default Journal ঠিক আছে

□  প্রতিটার Type সঠিক (Sale/Purchase/Bank/Cash/General)

□  Short Code সব আলাদা

□  Bank Journal-এ Default + Outstanding Account Check

Bank—

□  প্রতিটা Bank Account আলাদা Journal-এ

□  Dashboard-এ Card দেখা যাচ্ছে

□  Account Number সঠিক

□  Test Payment → Entry ঠিক জায়গায় গেছে

Payment Terms—

□  Net 30 (বা তোমার Standard) বানানো

□  প্রধান Customer-গুলোর Profile-এ Default বসানো

□  Test Invoice-এ Due Date নিজে এসেছে দেখেছি

Optional—

□  Online Payment Acquirer (লাগলে)
```
