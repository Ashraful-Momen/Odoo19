# Chapter 03 — One-to-One (১:১) Relationship

> **Golden Rule:** Odoo-তে dedicated `One2one` field **নেই**। ১:১ সবসময়
> **`Many2one` + `UNIQUE` constraint** দিয়ে model করা হয়।

```text
১:১  =  Many2one  +  UNIQUE
```

---

## এই Chapter-এ কী শিখবে

- ১:১ relationship-এর story ও concept
- Database-এ ১:১ কীভাবে হয় (FK + UNIQUE)
- Odoo model-এ কীভাবে লেখা হয় (code + FK/PK comment)
- UNIQUE না দিলে কী ভুল হয়
- Real-world example + Tips

## 1. Story

> একজন **Employee**-এর একটা **Passport** আছে।
> আর একটা **Passport** একজন **Employee**-এর।

```text
Employee 1 ───── 1 Passport
```

দুই দিকেই **একটা** → তাই ১:১।

---

## 2. Database-এ ১:১ কীভাবে হয়?

ধরো ২টা table:

```text
employees                        passports
------------------               --------------------------------
id (PK)                          id (PK)
name                             passport_no
                                 employee_id (FK)  ← references employees.id
```

FK হলো:

```text
passports.employee_id (FK)  →  employees.id (PK)
```

### কিন্তু! শুধু FK দিলেই ১:১ হয় না

FK থাকা মানে শুধু "relation আছে" — কিন্তু cardinality এখনো **১:এন**।

```text
Employee 1
   ↓
Passport A

Employee 1
   ↓
Passport B      ← এটা হলে ১:১ ভেঙে গেল (একজনের ২টা passport)
```

তাই **`employee_id`-কে `UNIQUE` করতে হবে**:

```text
passports.employee_id  UNIQUE
```

### Full ASCII — ১:১ relationship

```text
  employees (PK side)                passports (FK side)
┌──────────────────────┐         ┌──────────────────────────────────┐
│ id (PK)              │◄────────┤ id (PK)                         │
│ name                 │         │ passport_no                     │
└──────────────────────┘         │ employee_id (FK) → UNIQUE ◄──────┤
                                 └──────────────────────────────────┘
        একজনের শুধু একটা passport (কারণ employee_id UNIQUE)
```

> **মনে রাখো:** ১:১ = `FK + UNIQUE`। UNIQUE-ই ১:১-কে ১:এন থেকে আলাদা করে।

---

## 3. Odoo Model-এ ১:১ লেখা

```python
from odoo import models, fields


class Employee(models.Model):
    _name = "my.employee"        # Table name (DB: my_employee)

    # id = PK → Odoo auto-create করে

    name = fields.Char()         # Normal field

    passport_id = fields.Many2one(
        "my.passport",
        string="Passport",
    )                            # reverse FK → my_passport.id (PK)


class Passport(models.Model):
    _name = "my.passport"        # Table name (DB: my_passport)

    # id = PK → Odoo auto-create করে

    passport_no = fields.Char()  # Normal field

    employee_id = fields.Many2one(
        "my.employee",
        string="Employee",
        ondelete="cascade",
    )                            # FK → my_employee.id (PK)  ← মূল relation এখানে

    # ১:১ enforce করার জন্য UNIQUE constraint:
    _sql_constraints = [
        ("employee_uniq",        # constraint-এর নাম (unique হতে হবে)
         "UNIQUE(employee_id)",  # DB-level SQL: employee_id UNIQUE
         "One employee can have only ONE passport!"),
    ]
```

### Code-এ কী কী আছে

| Code | Type | DB-তে |
|------|------|-------|
| `id` (লেখা হয়নি) | **PK** | Odoo auto-create |
| `name` / `passport_no` | Normal field | normal column |
| `employee_id` | **FK** | `my_passport.employee_id` → `my_employee.id` |
| `_sql_constraints` UNIQUE | **১:১ enforce** | `UNIQUE(employee_id)` |

---

## 4. UNIQUE না দিলে কী হয়?

```python
employee_id = fields.Many2one("my.employee")   # FK only, UNIQUE নেই
```

তখন DB-তে:

```text
passports
-------------------------------
id   passport_no   employee_id
1    A1234         1
2    B5678         1      ← একই employee-এর ২টা passport = ১:এন হয়ে গেল!
```

অর্থাৎ **UNIQUE ছাড়া Many2one = ১:এন**, ১:১ নয়। এটা খুব common ভুল।

---

## 5. UNIQUE enforce করার ২টা উপায়

### উপায় ১ — `_sql_constraints` (DB-level, strong)

```python
_sql_constraints = [
    ("employee_uniq", "UNIQUE(employee_id)", "Duplicate employee!"),
]
```

DB নিজেই block করবে। **Recommended।**

### উপায় ২ — `@api.constrains` (ORM-level, custom logic)

```python
from odoo import api, models, fields, exceptions


@api.constrains("employee_id")
def _check_employee(self):
    for rec in self:
        if rec.employee_id:
            other = self.search([
                ("employee_id", "=", rec.employee_id.id),
                ("id", "!=", rec.id),
            ])
            if other:
                raise exceptions.ValidationError(
                    "এই Employee-এর already একটা Passport আছে!"
                )
```

> DB-level (`_sql_constraints`) বেশি reliable, কারণ সরাসরি SQL insert-ও block হয়।

## 6. Reverse Access (অন্য দিক থেকে পড়া)

`passports.employee_id` দিয়ে **passport থেকে employee** পড়া যায়।

Reverse-এ **employee থেকে passport** পড়তে চাইলে:

```python
class Employee(models.Model):
    _name = "my.employee"

    name = fields.Char()

    passport_id = fields.Many2one(
        "my.passport",
        string="Passport",
    )                            # reverse FK → my_passport.id (PK)
```

এখন:

```python
employee = self.env["my.employee"].browse(1)
employee.passport_id.passport_no   # → "A1234"
```

> **Tip:** ১:১-তে সাধারণত **একদিকে FK + UNIQUE** রাখাই clean। দুই দিকেই FK রাখা (circular) দরকার হলে Chapter 09 দেখো।

## 8. Tips & Tricks

1. **১:১ মনে রাখার trick:**
   ```text
   ONE ↔ ONE
   = Many2one + UNIQUE
   ```

2. **"কোন table-এ FK দিবো?"** → যেটা "belongs to" / "child" সেটাতে। Passport belongs to Employee → FK Passport-এ।

3. **UNIQUE কোথায়?** → FK column-এই UNIQUE, PK column-এ নয়।

4. **১:১ আর ১:এন confuse হলে:** FK column-এ UNIQUE আছে কিনা দেখো।
   - UNIQUE আছে → ১:১
   - UNIQUE নেই → ১:এন

5. **কখন ১:১ vs আলাদা field?** → related data আলাদা table-এ রাখা ভালো হলে ১:১ (প্রতি ১টা row-এ বড় data, বা optional info)।

---

## 9. Quick Recap

```text
১:১
  ↓
One ↔ One
  ↓
FK + UNIQUE constraint
  ↓
Many2one + _sql_constraints("UNIQUE(...)")
```

> **Super Rule:** শুধু `Many2one` দিলে সেটা ১:এন। ১:১ করতে **UNIQUE** লাগবেই।
