# Chapter 06 — M:N + Extra Data (Explicit Intermediary Model)

> **Golden Rule:** এম:এন relation-এর **মাঝখানে যদি extra business data** থাকে
> (date, grade, quantity, price...), তাহলে `Many2many` ব্যবহার কোরো না —
> **explicit intermediary model** বানাও।

```text
Simple M:N              →  Many2many
M:N + extra information →  Explicit model (Many2one + Many2one)
```

---

## এই Chapter-এ কী শিখবে

- কখন `Many2many` যথেষ্ট না
- Explicit intermediary model কীভাবে বানায়

## 1. Problem — Pivot Table-এ Extra Data লাগলে?

Student-Course relation-এ এখন দরকার:

```text
enrollment_date   (কবে enroll করলো)
grade             (কত নম্বর পেলো)
status            (active / completed)
```

`Many2many`-র pivot table-এ **শুধু ২টা FK** থাকে — extra column রাখার জায়গা নেই (cleanly)।

তাই relation-টাকে **নিজস্ব model** বানাও:

```text
Student
   ↓ (১:এন)
Enrollment   ← extra data এখানে
   ↓ (এন:১)
Course
```

```text
Student 1 ─── N Enrollment N ─── 1 Course
```

---

## 2. DB Structure

```text
my_student          student_enrollment            my_course
-----------         ---------------------         ---------
id (PK)             id (PK)                       id (PK)
name                student_id (FK)               name
                    course_id  (FK)
                    enrollment_date  ← extra
                    grade            ← extra
                    status           ← extra
```

> **মূল idea:** M:N-এর মাঝের pivot table-কে **upgrade করে একটা real model** বানাও, যাতে extra field রাখা যায়।

## 3. Odoo Model Code

```python
from odoo import models, fields


class Student(models.Model):
    _name = "my.student"           # Table name

    # id = PK → Odoo auto-create

    name = fields.Char()

    enrollment_ids = fields.One2many(
        "student.enrollment",      # comodel = intermediary model
        "student_id",              # inverse = FK field on enrollment
        string="Enrollments",
    )                              # reference → student_enrollment.student_id (reverse)


class Enrollment(models.Model):
    _name = "student.enrollment"   # Table name (intermediary model)

    # id = PK → Odoo auto-create (এখানে PK আছে!)

    student_id = fields.Many2one(
        "my.student",
        required=True,
    )                              # FK → my_student.id (PK)

    course_id = fields.Many2one(
        "my.course",
        required=True,
    )                              # FK → my_course.id (PK)

    enrollment_date = fields.Date()          # extra field
    grade = fields.Float()                   # extra field
    status = fields.Selection([
        ("active", "Active"),
        ("completed", "Completed"),
    ])                                        # extra field


class Course(models.Model):
    _name = "my.course"            # Table name

    # id = PK → Odoo auto-create

    name = fields.Char()

    enrollment_ids = fields.One2many(
        "student.enrollment",      # comodel = intermediary model
        "course_id",               # inverse = FK field on enrollment
        string="Enrollments",
    )                              # reference → student_enrollment.course_id (reverse)
```

### Code-এ কী কী আছে

| Code | Type |
|------|------|
| `Enrollment.id` | **PK** (intermediary model-এ আলাদা PK) |
| `student_id`, `course_id` | **FK** (২টা Many2one) |
| `enrollment_date`, `grade`, `status` | **extra data** |
| `Student.enrollment_ids` | reverse reference |

## 5. Real ERP Example — Sale Order Line

একটা **Order**-এ অনেক **Product**, একটা **Product** অনেক **Order**-এ থাকে।

Technically:

```text
Order M:N Product
```

কিন্তু Order-Product relation-এর মাঝে আছে:

```text
quantity, price, discount, tax, subtotal
```

তাই Odoo **Many2many নয়**, explicit model ব্যবহার করে:

```text
sale.order
      ↓ (১:এন)
sale.order.line   ← quantity, price, discount, tax
      ↓ (এন:১)
product.product
```

```python
class SaleOrder(models.Model):
    _name = "sale.order"
    order_line = fields.One2many("sale.order.line", "order_id")  # reference


class SaleOrderLine(models.Model):
    _name = "sale.order.line"
    order_id = fields.Many2one("sale.order")        # FK → sale_order.id (PK)
    product_id = fields.Many2one("product.product") # FK → product_product.id (PK)
    product_uom_qty = fields.Float()                # extra: quantity
    price_unit = fields.Float()                     # extra: price
    discount = fields.Float()                       # extra: discount
```

> এটাই **proper relational design**। ERP-র প্রায় সব "line" model এই pattern-ই।

## 6. Golden Rule

```text
Simple M:N
    ↓
Many2many

M:N + extra information
    ↓
Explicit intermediary model
    ↓
Many2one + Many2one + extra fields
```

এটা জানলে ERP-র অনেক database structure instantly বুঝতে পারবে।

---

## 7. Tips & Tricks

1. **কখন explicit model?** → relation-এ `date/qty/price/status` লাগলে **অবশ্যই** explicit model।

2. **Naming pattern:** intermediary model-এর নাম সাধারণত `X.line` বা `X.Y` (যেমন `sale.order.line`, `purchase.order.line`).

3. **Many2many-তে চাইলে extra data ও রাখা যায়** (pivot table-এ manual column), কিন্তু **clean ও maintainable না** → explicit model ভালো।

4. **Intermediary model-এর নিজের PK থাকে** (Many2many-র pivot-এর মতো নয়) — কারণ এটা এখন real model।

5. **দুই পাশেই One2many** দাও — parent দুটো থেকেই line-এ ঢোকা যাবে।

---

## 8. Quick Recap

```text
M:N + extra data
  ↓
Many2many NOT enough
  ↓
Explicit intermediary model (X → Line → Y)
  ↓
Many2one + Many2one + extra fields
```

> **Super Rule:** relation-এর নিজস্ব data থাকলে relation-কে **নিজস্ব model** বানাও।
