অবশ্যই। তুমি যদি **Odoo ORM + relational database** ভালোভাবে বুঝতে চাও, তাহলে শুধু `Many2one/One2many/Many2many` মুখস্থ করলে হবে না। তোমাকে **PK → FK → Cardinality → ORM abstraction → Join/Pivot → Reverse relation → Polymorphism → Circular dependency**—এই chain-টা মাথায় বসাতে হবে।

নিচের নোটটা এমনভাবে সাজালাম যাতে **যেকোনো নতুন ERP/CRM/e-commerce system দেখলেও database relation দেখে ORM বুঝতে পারো।**

# Odoo ORM — Complete Relationship Master Note

---

# 0. প্রথমে এই একটি Rule মাথায় বসাও

> **Database relation আগে বুঝবে, তারপর ORM relation বুঝবে।**

Odoo-তে:

```text
Database
   ↓
PK / FK
   ↓
Relationship
   ↓
Odoo ORM Field
   ↓
Python Object
```

অর্থাৎ:

```text
Database Truth
      ↓
ORM Representation
```

**ORM database relationship তৈরি করে না—ORM database relationship-কে সহজভাবে ব্যবহার করার interface দেয়।**

---

# 1. PK কী?

## Definition

**PK = Primary Key**

একটি table-এর প্রতিটি record-কে uniquely identify করে।

ধরো:

```text
student
----------------
id    name
1     Ashraful
2     Tanvir
3     Abdullah
```

এখানে:

```text
id = Primary Key
```

কারণ:

```text
1 → শুধু Ashraful
2 → শুধু Tanvir
3 → শুধু Abdullah
```

একই `id` দুইবার থাকতে পারবে না।

---

# 2. FK কী?

## Definition

**FK = Foreign Key**

একটি table-এর column যখন অন্য table-এর PK-কে reference করে, সেটাই FK।

ধরো:

```text
department
----------------
id    name
1     AI
2     Software
```

আর:

```text
employee
-------------------------
id    name       dept_id
1     Ashraful   1
2     Tanvir     1
3     Karim      2
```

এখানে:

```text
department.id
       ↑
       |
employee.dept_id
```

`employee.dept_id` হলো **Foreign Key**।

---

# 3. Relationship বুঝার Golden Question

যেকোনো system দেখলে শুধু এই প্রশ্ন করো:

> **একটা A-এর সাথে কতগুলো B থাকতে পারে?**

যেমন:

```text
1 Department → Many Employees
```

তাহলে:

```text
Department 1 ─────── N Employee
```

অর্থাৎ:

```text
One-to-Many
```

# 5. One-to-One — 1:1

## Story

ধরো:

> একজন Employee-এর একটি Passport আছে।

এবং:

> একটি Passport একজন Employee-এর।

তাহলে:

```text
Employee 1 ───── 1 Passport
```

---

## Database

```text
employees
----------------
id
name
```

```text
passports
----------------
id
passport_no
employee_id
```

এখানে:

```text
passports.employee_id → employees.id
```

কিন্তু শুধু FK দিলেই 1:1 হয় না।

`employee_id` অবশ্যই unique হতে হবে।

```text
employee_id UNIQUE
```

কারণ:

```text
Employee 1
   ↓
Passport A

Employee 1
   ↓
Passport B
```

এটা 1:1 ভেঙে দিল।

তাই:

```text
passports.employee_id UNIQUE
```

# 6. Odoo 1:1

Odoo-তে dedicated `One2one` field নেই।

সাধারণত:

```python
class Employee(models.Model):
    _name = "my.employee"

    passport_id = fields.Many2one(
        "my.passport",
        string="Passport"
    )
```

আর passport side:

```python
class Passport(models.Model):
    _name = "my.passport"

    employee_id = fields.Many2one(
        "my.employee",
        string="Employee"
    )
```

তারপর uniqueness/business constraint দিয়ে 1:1 enforce করা যায়।

### মনে রাখবে:

> **Odoo-তে 1:1 usually `Many2one + unique constraint` দিয়ে model করা হয়।**

# 7. One-to-Many — 1:N

এটাই Odoo-তে সবচেয়ে গুরুত্বপূর্ণ relationship।

## Story

একজন Manager-এর অনেক Employee আছে।

```text
Manager
   │
   ├── Employee 1
   ├── Employee 2
   ├── Employee 3
   └── Employee 4
```

তাই:

```text
Manager 1 ───── N Employees
```

---

# 8. Database Structure

```text
manager
-------------
id
name
```

```text
employee
-----------------
id
name
manager_id
```

FK:

```text
employee.manager_id
        ↓
manager.id
```

**Golden Rule:**

> One-to-Many relation-এর FK থাকে "Many" side-এ।

অর্থাৎ:

```text
Manager 1 ───── N Employee

FK → Employee table
```

---

# 9. Odoo Many2one

```python
class Employee(models.Model):
    _name = "my.employee"

    manager_id = fields.Many2one(
        "my.manager",
        string="Manager"
    )
```

এখানে:

```text
manager_id
```

একজন manager select করবে।

---

# 10. Odoo One2many

Manager model:

```python
class Manager(models.Model):
    _name = "my.manager"

    employee_ids = fields.One2many(
        "my.employee",
        "manager_id",
        string="Employees"
    )
```

এখানে:

```text
employee_ids
```

মানে:

> এই manager-এর অধীনে যত employee আছে।

---

# 11. সবচেয়ে Important Odoo Concept

এই দুইটা relation আসলে একই relationship-এর দুই দিক।

```text
Employee
    |
    | manager_id
    ↓
Manager
```

এবং:

```text
Manager
    |
    | employee_ids
    ↓
Employee
```

অর্থাৎ:

```python
Many2one
```

হলো **database side-এর মূল relation**।

আর:

```python
One2many
```

হলো তার **reverse view**।

### মনে রাখো:

> **Many2one stores the FK. One2many reads the reverse side.**

এটা মাথায় বসলে Odoo ORM-এর অর্ধেক শেষ।

# 12. One2many কেন FK রাখে না?

এটা খুব গুরুত্বপূর্ণ।

তুমি লিখলে:

```python
employee_ids = fields.One2many(
    "my.employee",
    "manager_id"
)
```

Odoo database-এ আলাদা:

```text
employee_ids
```

column তৈরি করে না।

বরং Odoo internally করবে:

```sql
SELECT *
FROM employee
WHERE manager_id = manager.id;
```

তাই:

```text
Many2one → FK
One2many → Reverse lookup
```

# 13. Many-to-Many — M:N

## Story

একজন Student অনেক Course নিতে পারে।

একটি Course-এ অনেক Student থাকতে পারে।

```text
Student A ─── Course 1
          ├── Course 2
          └── Course 3

Student B ─── Course 1
          └── Course 3
```

তাই:

```text
Student M ───── N Course
```

---

# 14. Database-এ M:N কীভাবে হয়?

Database সরাসরি:

```text
student
course
```

দুই table দিয়ে M:N efficiently store করে না।

মাঝখানে একটি table লাগে:

```text
student
---------
id
name
```

```text
course
---------
id
name
```

তারপর:

```text
student_course
-------------------
student_id
course_id
```

এটাই:

> **Pivot / Junction / Association table**

```python
course_ids = fields.Many2many(
```

# 18. কিন্তু Pivot Table-এ Extra Data লাগলে?

এটা খুব important।

ধরো:

Student এবং Course relation-এর মধ্যে তোমার দরকার:

```text
enrollment_date
grade
status
```

তখন simple Many2many যথেষ্ট না।

Instead:

```text
Student
   ↓
Enrollment
   ↓
Course
```

Model:

```python
class Enrollment(models.Model):
    _name = "student.enrollment"

    student_id = fields.Many2one(
        "my.student",
        required=True
    )

    course_id = fields.Many2one(
        "my.course",
        required=True
    )

    enrollment_date = fields.Date()
    grade = fields.Float()
    status = fields.Selection([
        ("active", "Active"),
        ("completed", "Completed"),
    ])
```

এখন:

```text
Student 1 ─── N Enrollment N ─── 1 Course
```

### Golden Rule

> **M:N relation-এর মাঝখানে যদি extra business information থাকে, তাহলে explicit model বানাও।**

# 27. Polymorphic Relationship কী?

এখন একটু advanced।

ধরো তোমার একটি:

```text
Attachment
```

model আছে।

Attachment যেকোনো object-এর হতে পারে:

```text
Employee
Invoice
Product
Customer
Sale Order
```

একটা attachment table-এ তুমি যদি আলাদা আলাদা FK রাখো:

```text
employee_id
invoice_id
product_id
customer_id
order_id
```

তাহলে design messy হয়ে যাবে।

তাই polymorphic relation concept:

```text
res_model
res_id
```

Example:

```text
attachment
-----------------------
id
name
res_model
res_id
```

Data:

```text
1  CV.pdf       hr.employee     10
2  Invoice.pdf  account.move    50
3  Image.png    product.product 20
```

এখানে:

```text
res_model = কোন model?
res_id    = কোন record?
```

# 29. Generic Relation কী?

Generic relation এবং polymorphic relation অনেক context-এ কাছাকাছি concept।

Simple definition:

> **একটি relation যেখানে target model fixed নয়; runtime-এ model + record identify করা হয়।**

Traditional FK:

```text
employee_id → hr.employee
```

Generic:

```text
model = "hr.employee"
id = 10
```

অর্থাৎ:

```text
Traditional FK:

employee_id
     ↓
employee

Generic:

model + id
     ↓
যেকোনো model
```

---

# 30. Polymorphic vs Normal FK

### Normal

```text
comment
---------
id
employee_id
```

শুধু:

```text
Employee
```

এর সাথে relation।

### Polymorphic

```text
comment
---------
id
res_model
res_id
```

এখন:

```text
Employee
Invoice
Product
Order
```

সবকিছুর comment হতে পারে।

---

# 31. Important Warning — Polymorphic FK

Normal FK-এর মতো database-level referential integrity সাধারণত সহজে enforce করা যায় না।

কারণ:

```text
res_id = 10
```

কিন্তু:

```text
10 কোন table-এর?
```

সেটা `res_model` বলে।

Database সাধারণ FK constraint-এর মতো সহজে:

```text
res_id → multiple possible tables
```

enforce করতে পারে না।

তাই application/ORM level validation গুরুত্বপূর্ণ।

# 32. Circular Relationship

এখন খুব গুরুত্বপূর্ণ বিষয়।

```text

   ↓
```

এটা:

> **Self-referential relationship**

এবং hierarchy তৈরি করতে খুব useful।

# 34. Circular Error কোথায় আসে?

ধরো:

```text
A → B
B → C
C → A
```

Graph:

```text
A
↓
B
↓
C
↓
A
```

এটা cycle।

যদি application বলে:

```text
A depends on B
B depends on C
C depends on A
```

তাহলে infinite dependency তৈরি হতে পারে।

# 35. ORM-এ Circular Dependency

ধরো:

```text
Model A
   ↓
Model B
```

আর:

```text
Model B
   ↓
Model A
```

Simple relationship সবসময় error নয়।

Example:

```python
class A(models.Model):
    _name = "model.a"

    b_id = fields.Many2one("model.b")
```

```python
class B(models.Model):
    _name = "model.b"

    a_id = fields.Many2one("model.a")
```

এটা technically possible।

Problem শুরু হয় যখন:

```text
A create → B create → A create → B create...
```

অথবা:

```text
A.compute()
    ↓
B.compute()
    ↓
A.compute()
```

> আমার approval-এর জন্য Ashraful-এর approval লাগবে।

```text
Ashraful
   ↓
Tanvir

Ashraful
   ↓
Tanvir

```

কখনো শেষ হবে না।

# 37. Circular Dependency-এর Solution

### Solution 1 — Direction ঠিক করো

একটা clear owner রাখো।

```text
Employee
   ↓
Manager
```

সবদিক থেকে dependency না বানিয়ে।

---

### Solution 2 — Nullable FK

```python
manager_id = fields.Many2one(
    "my.employee"
)
```

Top-level:

```text
CEO.manager_id = NULL
```

এতে hierarchy শুরু করা যায়।

---

### Solution 3 — Avoid recursive create

Bad:

```python
create_A()
    create_B()
        create_A()
```

Better:

```python
A create
B reference A
```

---

### Solution 4 — Use IDs after creation

প্রথমে:

```python
a = create_A()
```

তারপর:

```python
b = create_B({
    "a_id": a.id
})
```

এতে circular creation ভাঙা যায়।

# 38. Odoo Related Field

এটা আরেকটা powerful ORM feature।

ধরো:

```python
class Employee(models.Model):
    _name = "my.employee"

    department_id = fields.Many2one(
        "my.department"
    )

    department_name = fields.Char(
        related="department_id.name"
    )
```

এখন:

```python
employee.department_name
```

automatically:

```text
employee
 ↓
department_id
 ↓
name
```

# 40. Computed Field বনাম Related Field

### Related

```python
department_name = fields.Char(
    related="department_id.name"
)
```

Value অন্য field থেকে আসে।

### Computed

```python
total = fields.Float(
    compute="_compute_total"
)
```

তারপর:

```python
def _compute_total(self):
    for record in self:
        record.total = record.qty * record.price
```

এখানে calculation হচ্ছে।

---

# 41. Dependency

Computed field-এর ক্ষেত্রে:

```python
@api.depends("qty", "price")
def _compute_total(self):
    for record in self:
        record.total = record.qty * record.price
```

মানে:

```text
qty changes
      ↓
price changes
      ↓
recompute total
```

## সবচেয়ে গুরুত্বপূর্ণ ৭টা Rule

**১.** `PK` = **আমি কে?**

**২.** `FK` = **আমি কার সাথে connected?**

**৩.** `Many2one` = **FK ধরে রাখে।**

**৪.** `One2many` = **Many2one-এর reverse side।**

**৫.** `Many2many` = **Pivot/Junction table।**

**৬.** `M:N + extra business fields` = **নিজস্ব relation model।**

**৭.** `Polymorphic` = **FK-এর target fixed নয়; `(model, id)` দিয়ে target নির্ধারণ হয়।**

আর একটা **super rule**:

> **কোনো ORM field মুখস্থ করার আগে database-এ FK কোথায় আছে সেটা খুঁজে বের করো। FK খুঁজে পেলে relationship প্রায় সবসময় নিজে থেকেই বের হয়ে যাবে।**

এই mental model দিয়ে Odoo ছাড়াও **Laravel Eloquent, Django ORM, SQLAlchemy, Spring JPA/Hibernate, Prisma, TypeORM, ERPNext/Frappe ORM**—সবগুলোর relationship অনেক সহজে বুঝতে পারবে।
